# 221 — i18next 27 et react-i18next 18

- **Statut** : en cours
- **Dépend de** : 074 (ADR-0014), 217 (avis de licence)
- **Agents** : les deux (aucun effet sur les agents : bibliothèque de l'interface).

## Pourquoi

Dependabot propose i18next 27 seul (PR jlallement/bobine#11), et sa CI échoue au typage
(`src/shared/permissions.ts`). react-i18next 18 est la version majeure qui l'accompagne. Les deux
sont livrés dans l'app : on monte les deux ensemble, en corrigeant les ruptures par du vrai code et
en vérifiant chaque changement de comportement annoncé.

## Critères d'acceptation

- [ ] `i18next` et `react-i18next` en version exacte 27.x et 18.x.
- [ ] Typage strict conservé : pas de `any`, pas de `@ts-ignore` / `@ts-expect-error`.
- [ ] Chaque changement de comportement des guides de migration examiné (journal ci-dessous).
- [ ] Avis de licence régénérés, licences toujours MIT.
- [ ] `./scripts/verify` passe ; suite e2e complète verte, plus `--lang en base startup`.

## Plan

1. Monter les deux paquets (`pnpm add -D --save-exact`).
2. Corriger le typage : `strictInterpolationChecks` vaut `true` par défaut en 27 ; les tables de
   clés passées à `t()` sans valeurs se typent `ParseKeysWithoutVariables`.
3. Relire les changements de comportement (i18next 27, react-i18next 18) contre `i18nOptions`,
   `main/i18n.ts`, `renderer/src/i18n.ts`, les `<Trans>` et les essais.
4. Régénérer `THIRD-PARTY-NOTICES.md` et `scripts/third-party/inventory.json`.
5. `verify`, suite e2e complète (français), `base` et `startup` en anglais, captures regardées.

Pas de nouvelle dépendance ; `use-sync-external-store` disparaît (react-i18next 18 prend
`useSyncExternalStore` de React).

## Journal

### 2026-11-10

**Versions** : i18next 26.7.1 → **27.0.1**, react-i18next 17.1.13 → **18.0.1**. Les 27.1.0 et
27.1.1 existent mais ont moins d'un jour : la règle `minimumReleaseAge` de pnpm les refuse, et
`pnpm add` ajoutait une exception à `pnpm-workspace.yaml`. Pas d'exception à la règle de chaîne
d'approvisionnement pour une montée de dépendance : on reste sur 27.0.1 (Dependabot proposera la
suite). La 27.1.0 apporte l'héritage latéral des pluriels (`_other` si `_many` manque) : sans
effet ici, `fr.json` a déjà ses formes `_many`, vérifiées par `locales.test.ts`.

**Changements d'i18next 27 et ce qu'on en fait**

| Changement | Effet chez Bobine |
|---|---|
| Types : `strictInterpolationChecks` vrai par défaut — `t(clé)` exige les variables, et une union de clés contenant une clé à variables est refusée sans options | Seule rupture. Les tables de clés traduites sans valeurs passent de `ParseKeys` à `ParseKeysWithoutVariables` : `permissions.ts` (`KNOWN_TOOL_TITLES`), `mcp.ts` (`AppToolFamily`), `main/mcp/tools.ts` (`AppToolAbout`), `settings-search.ts` (`IndexedSetting`), `TurnLimitCard.tsx`. Plus strict qu'avant : une clé à variables y est refusée à la compilation. `Message` (`message.ts`) garde `ParseKeys`, ses valeurs étant passées à `t()`. |
| `fallbackLng` vaut `false` par défaut (plus de `dev`) | Aucun : `i18nOptions` le fixe à `DEFAULT_LANGUAGE`. |
| `returnEmptyString` vaut `false` (exécution et types) | Aucun : déjà `false` dans `i18nOptions`, et aucune valeur vide dans les JSON. |
| Codes de langue sans région remis en casse canonique (`cleanCode`) | Aucun : seulement `fr` et `en`, déjà en minuscules ; `BOBINE_LANG` passe par `isLanguage()`. |
| Codes de langue d'allure dangereuse refusés | Aucun : langues listées dans `supportedLngs`. |
| Journal et post-traitements propres à chaque instance | Déjà le cas : chaque instance (main, renderer, `createInstance()` des essais) appelle `.use(typography)`. |
| Objet renvoyé sans `returnObjects` : la clé plutôt qu'une phrase | Aucun : les clés de groupe sont refusées par le typage. |
| `/` n'est plus échappé | Aucun : `escapeValue: false`. |
| `createInstance(options)` fusionne les défauts tout de suite ; `keySeparator: false` ; appels pointés du magasin (`getResource('en.translation.x')`) et `*Escaped` retirés | Rien de tout cela n'est utilisé. |

**Changements de react-i18next 18 et ce qu'on en fait**

| Changement | Effet chez Bobine |
|---|---|
| Demande i18next ≥ 27.0.1 et React ≥ 18 | Satisfait (React 19). |
| `Trans` décode toujours les entités HTML, quel que soit `escapeValue` | Aucun : pas d'entité (`&…;`) dans `fr.json` ni `en.json`. Vérifié par les e2e (75 `<Trans>`). |
| `Trans` / `IcuTrans` suivent seuls le changement de langue | Mieux : plus besoin d'un parent qui se refait. |
| Options `react` propres à l'instance | Aucun : pas d'option `react`, ni `setDefaults()`. |
| `i18n` de `useTranslation` relit l'instance (plus une copie) | Aucun : `i18n.language` n'est lu qu'au rendu, jamais comparé à une valeur précédente. |
| `useSSR`, macro `icu.macro`, build UMD/AMD retirés ; `I18nContext` typé `undefined` possible ; augmentation `allowObjectInHTMLChildren` en option | Rien de tout cela n'est utilisé. |
| `use-sync-external-store` n'est plus une dépendance | Un paquet livré de moins (avis de licence : 187 paquets). |
